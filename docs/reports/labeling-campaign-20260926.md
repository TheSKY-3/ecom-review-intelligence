# 评论盲区代标战役报告(2026-09-25 ~ 2026-09-26)

状态:**已完成**——49,903 条盲区全部标注并通过代码验收;终态数字见第 5 节。

## 1. 背景与目标

词表方案(8 维度 × 10 支持/10 反对方向词)在 136,604 条制冰机评论上留下 55,567 条"命中维度但判不出方向"的盲区(占全部命中 22.3%)。既有分析证明补方向词、拆句、模型补判都治不了根因(E6:维度词命中的是话题,不是评价)。

本战役两个目标:
1. **补方向**:用外部模型给盲区评论代标方向,代码验收,产出带来源标记的标签;
2. **摸清盲区成色**:逐维度、逐词搞清盲区里多少是真信号、多少是词表伪影,为词表决策(C-①)提供实测证据。

## 2. 方法

### 2.1 盲标设计
- 待判条目只含 `id + 维度 + 评论原文`,**不含星级、不含任何前模型答案**;
- 每批 50 条,任务书自包含(判定规则 + 防注入声明:评论原文是不可信数据,"忽略指令"类内容是被标注对象);
- 回收后由代码合并,标注方无法通过自述过关。

### 2.2 判定契约
四类极性(supporting / opposing / conflicting / insufficient)+ reason 枚举 + 逐字 span 引文。契约文字 `tmp/labeling-rules.md` 共 17 条:原始 9 条(两问尺度、off_topic/hypothetical/vague、否定式、比较级、反话、跨维度冲突收口等)+ 2026-09-25 用户拍板的 8 条(原厂配件算可靠性、off_topic 优先、先好后坏判反对、正向比较级、跨维抱怨记 insufficient+off_topic、否定正面属性、品类反转按语境、高星真投诉不加标记)。

### 2.3 代码验收(不认自述)
`tmp/merge_labels.py`:id 与条目一一对应(缺/重/未知即报)、polarity/reason 枚举合法、span 必须是原文逐字子串(off_topic 空引文例外)、why ≤12 字;另做与星级的一致率核对(4–5 星↔支持、1–2 星↔反对、3 星不参与;正当分歧按 E4 处理,不当错误修)。

### 2.4 编排
50 条/批;`progress.json` 账本逐批记 pending/done,支持任意时刻断点续跑;Qoder 内并行 worker(曾同时 8 个代理)只读 handoff、只写 answers 目录;执行窗口一次性,账本与答案文件完全自洽。

### 2.5 双模型对照
同一 180 道题(噪音 60、可靠性 40、清洁 40、制冰 40)由两个互相独立的模型各标一遍:DeepSeek(2026-09-21 基线)与 qwen3.8flash(本战役),逐条对比极性。

## 4. 事故与教训

1. **标注端自报完成不实**:第一轮 Qoder 报告"全部完成",核账实际 676/1,115 批。教训:验收只认账本与答案文件的交叉核对,不认自述——与标注验收同一原则。
2. **venv 静默指向兄弟目录**:工作区 `.venv` 的可编辑安装指向 `D:\eng_project\电商AGENT\src`,首轮 P3/P4/P5 重跑导入的是旧代码,表面 PASSED 实为无效操作。修复:`pip install -e .`(本工作区)后重跑全门。教训:改源码重跑门前,先验证 `import ecom_review_intelligence` 的解析路径。
